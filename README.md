# Берлога-бот

Один бот вместо Carl-bot × Juniper × HoneyPot, без мини-игр и без «информации об играх».
Хостится из GitHub на bothost.ru, ставится обычным `npm install`.

## Что умеет

| Механика | Как выглядит |
|---|---|
| **Приветствие** | embed: аватар, «N-й в берлоге», возраст аккаунта, счётчик участников, бустеру — отдельная строка |
| **Прощание** | embed в том же стиле, отдельная цветовая схема |
| **Повышение уровня** | embed с новым уровнем и суммой XP, анонс в свой канал или в тот, где писали |
| **Анти-рейд** | лимит входов за окно → локдаун + максимальная верификация; кик молодых аккаунтов; кик левых ботов; откат вебхуков; алерт по интеграциям; `/panic` |
| **Автомод** | инвайты, ссылки, капс, флуд, массовые упоминания, много вложений; 3 нарушения за 10 мин → мут на 10 мин |
| **Мут → подвальск** | `/mute` добавляет роль с запретами во всех каналах и **разрешает писать в одном** `#подвальск`; канал и роль создаются сами |
| **Honeypot** | канал-ловушка: кто написал (включая вебхук) — бан/кик/мут на 28 дней, алерт в лог |
| **Starboard** | N реакций → пост в витрину, счёт обновляется, при падении ниже порога пост удаляется |
| **e621-фид** | раз в N минут в привязанный NSFW-канал пост по тегам; жёсткий блок несовершеннолетнего контента и gore/scat |
| **Реакции/верификация** | панель на кнопках: «Участник» и «18+» |
| **Модерация** | `/warn`, `/warnings`, `/kick`, `/ban`, `/clear`, лог действий |
| **Логи** | удаление/правка сообщений, входы/выходы, действия модерации |

Мини-игр, статистики по играм и «информации о людях» нет — по ТЗ.

## Автонастройка при первом запуске

Первый старт бот не ждёт команд: он сам находит по именам каналы и роли и прописывает их в настройки.

- `логи`, `караул`/`жалобы` → лог действий и лог модерации
- `starboard` → витрина, порог 3
- `honeypot` → канал-ловушка (действие — бан, алерт в мод-лог)
- `знакомство`/`вход` → приветствие и прощание
- роли `Админ`, `Модератор`, `Ведущий` → персонал (им можно шуметь)
- роль `Участник` → создаётся, если её нет
- роль `18+` → доступ в NSFW-раздел

В логе будет строка вида:

```
[info] автонастройка Берлога: логи -> #логи, starboard -> #starboard, honeypot -> #honeypot, ...
```

Дальше всё меняется через `/setup` — автонастройка запускается только один раз (флаг `bootstrapped`).

> **Чтобы верификация реально закрывала сервер**, на каналах-«только чтение» должен стоять запрет
> `ViewChannel` для `@everyone` и разрешение для роли `Участник`. Если каналы открыты всем,
> роль `Участник` — это просто метка, ничего не закрывающая.

## Быстрый старт локально

```bash
npm install
copy .env.example .env      # Windows
# nano .env                 # Linux/macOS
npm start
```

В `.env` минимум:

```
DISCORD_TOKEN=твой_токен
GUILD_ID=1568752097111965756   # чтобы команды появились сразу
```

## Деплой на bothost через GitHub

1. **Создай репозиторий** на GitHub (можно приватный) и залей папку:

   ```bash
   git init
   git add .
   git commit -m "berloga bot"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_АККАУНТ/berloga-bot.git
   git push -u origin main
   ```

   `node_modules`, `.env` и `data/` в репозиторий не попадают — они в `.gitignore`.

2. **bothost.ru** → «Создать бота» → тип **Node.js**.
3. Вкладка **GitHub**: подключи аккаунт, выбери репозиторий и ветку `main`, включи автодеплой
   (тогда каждый `git push` будет пересобирать бота).
4. **Команда установки:** `npm install`
   **Команда запуска:** `npm start`
5. Вкладка **Переменные окружения**: добавь `DISCORD_TOKEN` (и по желанию `GUILD_ID`, `E621_USER_AGENT`, `LOG_LEVEL`).
   Токен в код не вписывай никогда.
6. Запусти. В логах должно быть:

   ```
   [info] вошёл как ТвойБот#1234
   [info] команды зарегистрированы в Берлоге
   [info] e621-фид запущен
   ```

## Настройки в Developer Portal

- **Bot → Privileged Gateway Intents:** включи **Server Members Intent** и **Message Content Intent**.
  Без них не будет приветствий, уровней и автомода.
- **Bot → Public Bot:** можно выключить.
- **OAuth2 → URL Generator:** scopes `bot` + `applications.commands`, права — `Administrator`.

Готовая ссылка-приглашение (замени CLIENT_ID):

```
https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot%20applications.commands&permissions=8
```

> Без scope `applications.commands` слэш-команды зарегистрируются, но в клиенте не появятся.

## Команды

```
/setup welcome    channel:#вход [text] [title]
/setup farewell   channel:#вход [text] [title]
/setup levels     enabled:true channel:#общение
/setup starboard  channel:#starboard threshold:3 emoji:⭐
/setup honeypot   channel:#honeypot action:бан alert:#караул
/setup logs       action:#логи mod:#караул
/setup feed       channel:#nsfw-парни tags:"male anthro solo" interval:45
/setup feed-remove channel:#nsfw-парни
/setup antiraid   enabled:true limit:8 window:30 minage:10
/setup automod    rule:инвайты enabled:true
/setup automod    mentions:5 attachments:4
/setup staff      role:@Модератор
/setup verify     member_role:@Участник nsfw_role:@18+

/mute user:@кто-то duration:2h reason:спам
/unmute user:@кто-то
/warn user:@кто-то reason:флуд
/warnings user:@кто-то
/kick | /ban | /clear
/rank [user] | /top
/panic state:включить
```

Тексты приветствия понимают подстановки в embed-е: `{user}`, `{count}` можно вписать в `text`
(проще — просто оставить пустым, текст по умолчанию уже готовый).

## Как это работает внутри

**Подвальск.** `/mute` создаёт роль `🔇 Заглушенные` и канал `#подвальск` (если их нет),
потом вешает на роль запрет `SendMessages` во всех каналах и явное разрешение в `#подвальск`.
Если указан срок — дополнительно ставится нативный таймаут (до 28 дней) и таймер на снятие роли.

**Honeypot.** Канал должен выглядеть обычно, но в него никто не пишет. Любое сообщение =
бан (по умолчанию), удаление сообщения, алерт. Вебхуки удаляются, сообщения от них — тоже повод.

**Анти-рейд.** Три слоя: возраст аккаунта, частота входов, аудит-лог. Аудит проверяется раз в 20 секунд:
`WebhookCreate` и `BotAdd` откатываются автоматически, `IntegrationCreate` — только алерт,
потому что удаление интеграций через API Discord не даёт.

**e621.** `https://e621.net/posts.json?tags=...`, `User-Agent` задаётся в `E621_USER_AGENT`.
Хардкод-запреты (`-cub -young -underage -loli -shota -gore -scat`) добавляются к любым тегам,
их нельзя отключить из команды. Пост уходит только в канал с флагом NSFW.

## Роли и e621 (обновление)

**Самостоятельные роли.** `/roles` публикует панель с четырьмя меню:

- **Возраст** — 🟢 13-15, 🟡 16-17, 🔴 18+ (одна на выбор);
- **Кто ты** — 💙 Парень, 💗 Девушка, 💜 Небинар;
- **Цвет ника** — 6 цветов, красят имя;
- **Украшения** — 🎀 Фембойчик, 🤪 Глупи, 🔔 Уведомления, 📖 О себе, 🎮 Играю, 🎨 Рисую (до трёх).

**Гейт 18+.** Кто выбрал 13-15 или 16-17 — не получит ни возрастную роль 18+, ни доступ в 🔞:
кнопка в верификации и меню отвечают отказом. Снял возрастную роль — гейт снимается сам.

**e621: 24 поста в сутки в каждый канал (1 в час).** Теги уже прописаны по каналам:

| Канал | ID | Теги |
|---|---|---|
| nsfw-обычное (ванилла, МЖ) | 1568765195436949598 | `anthro female male -gay -lesbian` |
| nsfw-парни (геи) | 1568765199455100960 | `anthro male gay` |
| nsfw-девушки | 1568765204194529501 | `anthro female lesbian solo` |

Плюс ко всему запросу добавляется `score:>40` (чтобы не второсортный арт) и хардкод-запреты.
Ручной пост: **`!e621`** (без слэша) или `/e621` — канал определяется сам, чаще раза в минуту нельзя.

> по коду и расписанию. На bothost проверь первый час по логам: `[debug] e621 -> #nsfw-парни`.
> Если хостинг тоже в РФ и e621 режется — нужен прокси или хостинг вне РФ.

## Приватность: бот заперт на один сервер

Сервер, на котором боту разрешено работать: **1568752097111965756** (вшит в `src/guard.js`
как `DEFAULT_GUILD`). Логика:

- при старте бот **выходит** из всех серверов, которых нет в списке;
- при попытке пригласить его куда-то ещё — выходит сразу же (`GuildCreate`);
- команды, модерация, автомод, уровни, реакции и логи на чужих серверах **не срабатывают**
  (проверка стоит в каждом обработчике событий);
- слэш-команды регистрируются только в разрешённых серверах — в новых они просто не появятся.

Переопределить список, если понадобится:

```
ALLOWED_GUILDS=1568752097111965756,второй_сервер_ид
```

Ещё два шага вне кода, которые стоит сделать:

1. **Developer Portal → Bot → Public Bot = OFF.** Тогда по твоей ссылке-приглашению бота
   не сможет добавить никто, кроме тебя.
2. **Ссылку-приглашение не публиковать.** Сам ID сервера секретом не является,
   приглашение — фактически ключ. Замок страхует, но не рекламируй.

## Ограничения, о которых лучше знать

- **Владелец сервера обходит все запреты** — если ты смог написать в `#правила`, это не баг бота
  и не ошибка прав. Проверяй с обычного аккаунта.
- **Файловое хранилище.** Всё лежит в `data/store.json`. На хостингах с «чистым» диском при
  передеплое файл может обнулиться: включи постоянное хранилище, если bothost его даёт,
  иначе периодически скачивай `data/store.json` через файловый менеджер.
- **Таймеры мута живут в памяти.** После рестарта таймеры сбрасываются; роль останется,
  пока её не снимут `/unmute` или нативный таймаут (если срок был ≤28 дней).
- **`/clear` не удаляет сообщения старше 14 дней** — это ограничение Discord.
- **Один процесс = один токен.** Не запускай бота одновременно локально и на bothost:
  два подключения к шлюзу конфликтуют.
